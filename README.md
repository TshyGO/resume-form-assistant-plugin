# 简历灵填助手 Resume Pro

一个免费的网申填写工具，由**桌面程序**和**浏览器插件**两部分组成。

桌面程序保存你的简历模板、「我的信息」和 AI 设置，也管理投递记录；浏览器插件只负责在网申页面上填写。打开招聘网站的网申页面，在浏览器侧边栏点「一键 AI 填写」，插件会读取网页表单，由桌面程序转发给你配置的 AI，匹配姓名、手机号、邮箱、学校、专业、经历等字段。

手里只有 PDF 或 Word 简历，也可以在桌面程序里让 AI 整理成模板。

> 软件完全免费并开源。AI 功能需要你自己配置一个 OpenAI 兼容接口，接口是否收费取决于你使用的模型服务商。
>
> 支持的系统：**macOS（Apple 芯片）** 和 **Windows（x64）**；浏览器：**Chrome** 和 **Edge**（116 或更新版本）。

## 小白直接看这里

不需要会代码，不需要安装 Python，也不需要安装 Node.js。

整个流程只有五步：

1. 安装桌面程序
2. 安装浏览器插件，并和桌面程序连接
3. 在桌面程序里配置 AI
4. 在桌面程序里导入自己的简历
5. 打开网申页面，在浏览器侧边栏一键填写

**从旧版（0.4.0 及更早）升级的用户**：插件里原来的模板、「我的信息」和 AI 配置会自动迁到桌面程序，见 [从旧版升级](#从旧版升级)。

## 1. 安装桌面程序

打开 [桌面程序下载页](https://github.com/TshyGO/resume-form-assistant-plugin/releases?q=desktop-v&expanded=true)，找标签为 **`desktop-vX.Y.Z`** 的最新正式版：

- macOS（Apple 芯片）：下载 `.dmg`
- Windows：下载 `.msi` 或 `-setup.exe`

安装包目前没有商业签名，第一次打开时系统可能拦一下，处理办法见 [安装与升级说明](docs/desktop-mvp/install-and-update.md#2-安装包没有签名)。

桌面程序关掉窗口后会留在后台，插件需要它时也会自动把它拉起来。

## 2. 安装浏览器插件并连接桌面

Chrome 用户优先从 [Chrome 商店安装](https://chromewebstore.google.com/detail/diagjmploldedipjdenmecmjokckelkl)。

需要手动安装时，打开 Releases 找标签为 **`vX.Y.Z`** 的插件正式版，下载 `resume-pro-vX.Y.Z-chrome.zip` 并解压到一个固定文件夹（之后不要删），然后：

1. 地址栏输入 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 打开右上角的「开发者模式」
3. 点击「加载已解压的扩展程序」，选中解压出来、能直接看到 `manifest.json` 的那一层文件夹

安装成功后建议把 Resume Pro 固定到工具栏。**装完插件后重启一次浏览器**，让浏览器读到桌面程序写好的连接注册。

然后点工具栏的 Resume Pro 图标。浏览器会打开 Resume Pro 侧边栏（左右位置由浏览器设置决定）：

- 显示「这个浏览器还没和桌面配对」：点「复制扩展 ID」，到桌面程序「设置 → 浏览器连接」里粘贴完成配对。
- 显示「需要先安装桌面程序」：回到第 1 步。
- 显示正常的模板和字段：已经连上了。

### 已安装用户如何升级

商店版会自动更新。开发者模式加载的插件不会自动更新：下载新版 ZIP，覆盖原文件夹后在扩展页点「重新加载」即可。桌面程序下载新版直接安装，数据原样保留。

## 3. 在桌面程序里配置 AI

打开桌面程序，进入「设置 → AI 设置」，添加一个服务商：

```text
接口地址   例如 https://api.openai.com/v1
API Key   你自己的 Key
模型       点「获取模型」后从下拉里选，例如 gpt-4o-mini
```

只支持 OpenAI Chat Completions 兼容接口；国内大多数模型服务都提供这种接口。可以添加多个服务商，选一个作为「当前使用」。

API Key 保存在系统凭据库（macOS 钥匙串 / Windows 凭据管理器）里，不写进插件，也不进桌面备份。

请尽量使用 `https://` 开头的地址；`http://` 是明文传输，经过公共 WiFi 或不可信网络时可能被截获。

### API 配置看不懂怎么办

可以把它简单理解成：

```text
Resume Pro
负责读取网页和填写表单

AI 模型
负责判断“这个输入框应该填什么”
```

软件不会赠送模型额度，也不会替你注册 API。

## 4. 在桌面程序里导入自己的简历

打开桌面程序的「简历」页，有两种方式。

### 方法 A：用 PDF、Word 或 TXT 简历生成模板

1. 在「简历」页选择 AI 解析，上传 PDF、Word `.docx` 或 TXT 简历
2. 确认发送前的提示（会显示发给哪个服务商、多少字）
3. 等待 AI 提取，完成后直接生成一个新模板并设为当前

PDF 和 Word 会先在本机提取文字，再把文字发给 AI；扫描件、加密 PDF 提取不到文字时会明确提示，可以换成 Word 或 TXT，或先 OCR 再导出文字版 PDF。

AI 可能漏掉或理解错个别字段，解析完在模板里核对，也可以导出 Excel 修改后再导回来。

### 方法 B：自己制作 Excel 模板

新建一个 Excel，第一行固定写三列：

| 一级分类 | 字段名 | 值 |
| --- | --- | --- |
| 基本信息 | 姓名 | 张三 |
| 基本信息 | 手机号 | 13800000000 |
| 基本信息 | 邮箱 | example@qq.com |
| 教育背景 | 学校 | XX大学 |
| 教育背景 | 专业 | 材料科学与工程 |
| 教育背景 | 学历 | 硕士 |
| 教育背景 | 入学时间 | 2023-09 |
| 教育背景 | 毕业时间 | 2026-06 |
| 实习经历 | 公司 | XX公司 |
| 实习经历 | 岗位 | 研发实习生 |

保存成 `.xlsx` 或 UTF-8 编码的 `.csv`，在「简历」页导入。第二列「字段名」不要留空；把信息拆细（学校、专业、学历分开写）更容易匹配网页表单。

「简历」页下方还有「我的信息」：籍贯、户口、家庭成员这类网申常问、简历里通常没有的内容，填一次所有网站共用。

## 5. 开始填写网申

1. 打开公司的网申页面（之前已经打开的，刷新一次）
2. 点击工具栏的 Resume Pro 图标，打开侧边栏
3. 在「当前模板」选择要使用的简历
4. 点击「一键 AI 填写」
5. 等待匹配完成，检查填写结果

填写成功的字段会短暂高亮，侧边栏会提示本次填写了多少个字段。AI 还没配置时，侧边栏会提示并提供「打开桌面 AI 设置」。

**提交网申之前请自己完整检查一遍。** 插件不会替你提交。

目前已经对普通输入框、文本框、下拉框、单选框，以及部分日期选择器和级联选择控件做了兼容。遇到高度定制的网页控件时，仍可能需要手动填写。

## 6. AI 没填上的字段怎么办

1. 先点击网页里没填上的输入框，例如「学校」
2. 再点击 Resume Pro 侧边栏里的「学校」字段

插件会把内容填进刚才点击的输入框；网页控件不接受写入，或输入框里已经有内容时，会改为复制到剪贴板，按 `Ctrl + V`（macOS 为 `⌘ + V`）粘贴即可。侧边栏的「简历字段」页可以搜索全部字段。

## 7. 多套简历怎么用

在桌面程序「简历」页可以保存多套模板（最多 25 套），例如研发岗、产品岗、国企岗、英文简历。填写不同岗位之前，在侧边栏切换「当前模板」即可，切换会同步到桌面。

## 从旧版升级

0.4.0 及更早的插件把模板、「我的信息」和 AI 配置存在浏览器里。升级到 0.4.1 后：

1. 先安装桌面程序并完成连接（第 1、2 步）
2. 插件会自动把旧数据发给桌面，并把桌面切到「简历」页
3. 在「简历」页顶部核对要导入的内容，点「导入到桌面」。桌面里已经有「我的信息」时，会让你选保留哪一份
4. 导入完成后，插件自动清掉自己那一份旧数据

几点说明：

- **确认之前，插件里的数据不会删除。** 点「不导入」也一样，之后可以在插件状态页重新发送。
- 「我的信息」里看起来像密码、验证码的项不会迁移；超过 24 KB 或超过 25 个的模板也不会迁移，可以在插件状态页下载成 CSV，再到桌面「简历」页导入。
- AI 配置没能导入时（例如系统凭据库暂时不可用），简历照样导入，旧 API Key 会留在插件里，可以在插件状态页复制，到桌面「设置 → AI 设置」里填入后再删除。

插件状态页的入口：侧边栏底部的「插件状态」，或右键工具栏的 Resume Pro 图标选「选项」。浏览器没有侧边栏功能时，点工具栏图标会直接打开它。

## 常见问题

### 点击图标后没有打开 Resume Pro 侧边栏

先检查：

1. `chrome://extensions` 或 `edge://extensions` 中 Resume Pro 是否已开启
2. 是否已点击浏览器工具栏中的 Resume Pro 图标；侧边栏的左右位置由浏览器设置决定
3. 网申页面是否已刷新，以及当前页面是不是浏览器内部页面

例如下面这些页面无法注入普通扩展内容：

```text
chrome://extensions
chrome://settings
edge://extensions
```

请到普通网页测试。

### 提示“AI 还没有配置”或“连不上桌面”

AI 设置和简历都在桌面程序里。先确认桌面程序已安装并能打开，侧边栏里没有「未配对」「需要安装桌面程序」之类的提示；然后在桌面「设置 → AI 设置」里确认有一个服务商被设为「当前使用」，并填好了接口地址、模型和 API Key。

### 提示“AI 接口请求失败”

常见原因：

1. API Key 错误或失效
2. API 余额不足或被限流
3. 模型名称写错
4. 接口地址写错
5. 服务商接口并不兼容 OpenAI Chat Completions
6. 当前模型没有权限使用

侧边栏的「填写诊断」会写明失败类别（认证、限流、超时、网络等），不含 Key 和简历内容，可以截图反馈。

### Excel 导入失败

Excel 在桌面程序「简历」页导入。请确认：

1. 文件是 `.xlsx` 或 UTF-8 编码的 `.csv`
2. 第一行是表头
3. 前三列依次为「一级分类 / 字段名 / 值」
4. 每一条数据的「字段名」都有内容

插件只读取第一个工作表。

导入是「全有或全无」的：只要有一行缺「字段名」，整个文件都不会生效，模板保持原来的内容。提示条会一次列出所有出问题的行号，按行号补好再导入一次即可。

如果出问题的行特别多，提示会变成「共 N 行缺少「字段名」」并提醒检查整列——这种情况通常是插入或删除列时把第二列整体挪位了。

手工编辑表格时最容易漏的是只填了「一级分类」和「值」、忘了中间那列。

### AI 填错了怎么办

直接手动修改即可。

自动填写完成后一定要检查，尤其是：

```text
日期
学历
证件类型
政治面貌
城市和地区
级联下拉框
多段教育或工作经历
```

这些字段在不同招聘网站上的结构差异较大。

### 某个网站完全填不了

欢迎提交 Issue：

**[提交问题或兼容性反馈](https://github.com/TshyGO/resume-form-assistant-plugin/issues)**

如果方便，建议提供：

```text
招聘网站名称
具体页面类型
无法填写的字段
错误提示
页面截图
```

请记得遮掉姓名、手机号、邮箱、身份证号等个人信息。

## 隐私说明

简历模板、「我的信息」、投递记录和 AI 设置保存在你电脑上的桌面程序档案里，不上传到我们这里——我们没有服务器。API Key 保存在系统凭据库（macOS 钥匙串 / Windows 凭据管理器）里，不写进档案，也不进桌面备份。浏览器插件本身不再保存简历或 Key。

仓库里不包含任何真实用户简历数据，测试数据均为匿名示例。

使用「一键 AI 填写」时，插件把待匹配的网页字段信息，以及当前简历模板和「我的信息」中的相关字段交给桌面程序，由桌面程序发往你在桌面配置的 AI 服务商。密码、验证码类的网页字段和资料不会发送。

在桌面「简历」页用 AI 解析简历时，PDF 和 Word 会先在本机提取文字，但提取出的文字仍会发送到你配置的 AI 服务商。不要把“本地提取”理解为“简历内容完全不会上传”。

因此，请自行确认所使用 AI 服务商的隐私政策和数据处理规则。完整说明见 [隐私政策](docs/privacy-policy.md)。

API Key 请勿分享给他人，也不要提交到公开 GitHub Issue。

## 主要功能

- 桌面程序统一管理多套简历模板、「我的信息」、AI 服务商和投递记录
- 「我的信息」：籍贯、户口、家庭成员这类简历里没有的字段填一次，所有网站共用
- AI 自动匹配网页网申字段（请求由桌面程序转发）
- PDF / Word / TXT 简历 AI 解析，Excel / CSV 模板导入导出
- OpenAI 兼容接口，可配置多个服务商
- 普通输入框、文本框、下拉框、单选框填写
- 部分日期选择器和级联下拉兼容
- 字段快捷点击填写和复制
- AI 填写结果高亮提示
- 浏览器原生侧边栏中的填写与字段查找
- 保存岗位、确认投递、填写留档到桌面的申请记录

### AI 填写耗时与诊断

点击「一键 AI 填写」后，按钮显示扫描、AI 匹配秒数和填写阶段。完成或失败后，展开的「填写诊断」保留扫描、匹配往返、API（含响应体读取）、填写和总耗时，以及字段数量和用户 prompt 字节数；可在只读文本框中选择复制。未执行或未取得的阶段不会显示成零耗时。

- AI 等待超过 90 秒仅显示慢响应提醒，不自动取消。用户可随时点击「取消 AI 等待（保留本地匹配）」主动终止请求，包括响应体读取；取消不保证上游停止计算或停止计费。浏览器扩展生命周期、网络或上游服务仍可能自行中断请求。
- 需要 Chrome / Edge 116 或更新版本。提示词在扩展隐藏文档中的独立 Worker 里组装，经 service worker 用一条可断开的 Native Messaging 长连接交给桌面程序，由桌面发往服务商；取消即断开连接。浏览器退出、扩展重载仍会中断任务。
- HTTP、网络、用户取消、返回格式错误分别提示。AI 失败或手动取消时仍使用已验证的本地匹配结果，明确显示部分完成；不会自动重试或更改用户接口配置。慢响应提示说明可能与上游模型、中转、网络和输入量有关，不在缺少实测证据时断言一定是上游故障。
- 对明确的教育、工作、项目等字段，只发送相关的完整简历分组，保留多段经历及其关联字段。含糊、跨领域或无相关候选时回退全量，自定义未知分组始终保留。不采用固定 Top N 截断。
- 诊断摘要只包含版本、计数、字节数、耗时和标准错误类别，不包含接口地址、API Key、简历内容或上游错误原文。截图时仍需注意周围网页和模板本身的个人信息。

目前不做本地立即填写 / AI 异步补齐，不修改简历解析请求。请求大小下降不代表实际延迟按比例下降；真实模型的准确率和耗时仍需在同一模型、接口及表单上对比验证。

### AI 辅助新增条目（实验功能）

当网页只显示一条论文或经历时，可点「AI 辅助新增条目（先预览）」。插件把候选新增按钮的编号、类型和条目数量交给 AI 规划；此阶段不发送简历正文。你确认新增清单后，插件逐次点击、检查新输入框出现，再重新扫描并请求 AI 填写这些分组的空文本字段。

- 支持范围：明确标注的论文、教育经历／教育背景、工作经历、项目经历。需在 `section` 或 `role=group` 分组内，有匹配标题、独立 `fieldset` 条目及唯一的 `button[type=button]` 新增按钮。每次最多新增 5 条；结构不明确时回退手动操作。
- 若模板没有正式「工作经历」记录，会用「实习经历」推导通用工作分组的条目数，兼容默认解析格式；两类同时存在时不自动混合，实习分组需另行核对或手动处理。
- 只允许枚举到的新增按钮与本地数量上限。AI 不能提供代码、任意选择器、导航、提交或删除操作；页面文本只作为数据。可在规划和新增期间停止。
- 只填相关分组的空文本框／文本域，写入前再次检查已有内容；写入后短暂等待并读回值确认。下拉框、日期等复杂控件暂不纳入这个辅助模式，仍可手动填写。短时读回不等于网站服务端已保存，提交前必须核对。
- 按钮变化、条目数量异常、网页重建已有字段或 2.5 秒内未确认新增，立即停止，不重复点击。已经新增的空条目不自动删除；网页自己的新增操作可能触发保存，确认前请留意。
- 这是可选辅助入口，不改变原来的「一键 AI 填写」方式。通常需要两次模型调用（规划 + 匹配），并非所有招聘网站的通用自动投递代理。

### 桌面程序连接（D07）

侧边栏的简历条目和 AI 填写都经桌面程序完成；「更多工具」里还有「保存岗位到桌面端」和「确认已投递」，这些操作会在网页上打开相应的确认控件。点保存后先核对识别出的公司和岗位，确认后才写入桌面。**桌面不可用时，简历条目和 AI 填写不可用，保存岗位和确认投递会留在待同步队列里。**

几条不能含糊的规则，改这块代码前先看一眼：

- **「待同步」不等于「桌面已保存」。** 只有桌面持久化并回了 `resultId`，界面才允许说已保存。全部文案集中在 [`link/copy.mjs`](link/copy.mjs)，`tests/link-degradation.test.js` 按 §9 降级矩阵逐行核对。
- **「未安装」和「未配对」是两件事。** 装了但没配对时要说去桌面粘贴扩展 ID，不能说没装。
- **队列有两层。** 桌面当时不在，或精确重复还没选定 → `SaveIntent`（没有 messageId、没有申请 UUID、没有 epoch）。桌面在线且没有精确重复时，同一次保存会立刻写成 Bound outbox 并发送 `job.save`（新建，阶段是已保存，不是已投递）；有精确重复才问「使用已有 / 新建一条」。同公司的另一个岗位直接新建。Bound outbox 铸 `messageId`、盖当时的 `sourceRestoreEpoch`。两者都存在 `chrome.storage.local`，只用 `desktopSaveIntents` / `desktopOutbox` / `desktopClientInstanceId` / `desktopPairing` 四个 key；D08 的填写留档再加一个 `desktopFillRecords`（同样两层：未选申请的留档意图 → 选定之后才是 `fill.submit`）。
- **`sourceRestoreEpoch` 盖上就不改。** 重试时信封换成最新握手身份，载荷不换。桌面恢复过备份之后，旧 epoch 的消息一律暂停，只能走 `outbox.reconcile`，由用户决定关联 / 丢弃 / 另存。
- **重试沿用原 `messageId`。** 换 ID 就是第二条申请。

### 填写留档与简历快照（D08）

配对过桌面程序的用户，每次「一键 AI 填写」或「AI 辅助新增条目」结束后，侧边栏会问一句要不要把这次填写留档到桌面。留档记的是结果和计数（写进网页几项、几项未确认、耗时、用的哪个模板），**不记网页上填了什么**；默认附上一份这次用的简历模板拷贝（快照），可以取消勾选。

- **快照在填写开始时冻结。** 之后改模板不改它；桌面没开时先存在扩展自己的 IndexedDB，桌面可用后按块上传，传完才删本机副本。桌面里能从时间线打开它，并注明快照不能证明网站收到了什么。
- **留档不等于投递。** 任何留档文案都不说投递；投递之后仍然要点「确认已投递」。
- **从未配对的用户看不到这张卡片**，也不会在本机存任何东西。

改这块代码前看 [`docs/superpowers/plans/2026-09-11-d08-pr-breakdown.md`](docs/superpowers/plans/2026-09-11-d08-pr-breakdown.md)。模块：`link/fillrecords.mjs`（留档意图与 allowlist）、`link/snapshot.mjs`（快照格式）、`link/staging.mjs`（IndexedDB 暂存）、`link/uploads.mjs`（分片上传、游标、修复）。真实浏览器端到端：`python desktop/scripts/d08_browser_check.py`。

协议校验器不是这里写的，是 `desktop/crates/protocol/js/` 的副本，`tests/protocol-vendor.test.js` 锁死两边一致。改协议请改源文件再复制过来。

开发期把桌面程序注册成 Native Messaging host 的办法见 [`desktop/DEV-NATIVE-MESSAGING.md`](desktop/DEV-NATIVE-MESSAGING.md)。配对之后要重新加载扩展或重启浏览器，否则新写的注册不生效。

### 本地开发安装

功能和界面测试怎么拉起 dev（桌面端 + 插件 + 连接注册，Windows / macOS 通用）见 [`docs/dev-quickstart.md`](docs/dev-quickstart.md)，不需要打包。

克隆项目：

```bash
git clone https://github.com/TshyGO/resume-form-assistant-plugin.git
```

然后在 Chrome 或 Edge 的扩展管理页开启开发者模式，选择「加载已解压的扩展程序」，加载仓库根目录即可。

不需要构建步骤。

node --test tests/*.test.js
