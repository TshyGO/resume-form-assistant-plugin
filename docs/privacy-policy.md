# 网申快填隐私政策

最后更新：2026-10-14


网申快填是一个求职网申的填写辅助工具，由浏览器扩展和桌面程序两部分组成。
这份政策说明它**收集什么、不收集什么、数据去了哪里**。

## 一句话

简历、申请记录、附件保存在你自己的电脑上。主动使用 AI 时，相关内容发给**你自己配置的**服务商。
自动错误报告要你同意后才开启；也可以预览后手动反馈问题。报告先去掉可能的个人信息，发到我们的 Cloudflare 中转，再由 Muse 整理为 GitHub issue。
独立的使用数量统计开关默认开启、可以随时关闭；首次发送前显示说明。下面描述启用统计外发的桌面版本的行为，开发、测试、CI 和未配置统计外发的构建不发送使用统计。插件主动使用信号通过本机桌面处理，插件不直接连接统计服务。


## 数据存在哪

| 数据 | 位置 |
| --- | --- |
| 简历模板、「我的信息」、申请记录、回复证据、附件、待办、备份 | 桌面程序档案：Windows `%LOCALAPPDATA%\ResumePro`，macOS `~/Library/Application Support/ResumePro` |
| AI 服务商设置（地址、模型） | 桌面程序档案目录下的设置文件，不含 Key |
| AI API Key | Windows 凭据管理器 / macOS 钥匙串。不进档案、不进备份、不进日志 |
| 使用统计选择、告知版本、独立随机安装编号及最近尝试日期 | 桌面数据目录下的独立 `telemetry-state.json`；旁边的 `telemetry-initialized` 仅用于防止状态文件丢失后自动重新开启，不含编号。两者不进入档案数据库、备份、导出或诊断报告 |
| 扩展侧 | 浏览器的 `chrome.storage.local`：侧栏界面状态、与桌面的待同步队列、最近 200 次已处理填写的去重 ID 和结果、旧数据迁移状态。去重记录不含网页填写值。迁移完成后不存简历、不存 Key；只有没能迁过去的部分（见下段）暂留，直到你取回或删除 |

从 0.4.0 升级时，扩展里旧版留下的模板、「我的信息」和 AI 配置（含 Key）会在你于桌面确认后迁入桌面，随后从扩展里删除；迁移只经本机 Native Messaging，不经过网络。没能迁移的部分（桌面拒收的模板、桌面没导入的 Key）留在扩展里，你可以在扩展状态页取回或删除。

卸载扩展会清掉扩展侧的存储；卸载桌面程序**默认保留**上面那个档案目录，要删得在卸载器里单独确认一次。

## 会发到外面的东西

以下 AI 功能会把用户内容发到你自行配置的接口，均由你主动触发：

1. **扩展的「AI 填写」及「AI 辅助新增条目」**：扩展把当前表单的字段说明和相关的简历片段交给本机的桌面程序，由桌面发给你在桌面设置里选为「当前使用」的 OpenAI 兼容接口；辅助新增条目时会发送页面中候选新增按钮的说明及条目数量，以生成供你预览的新增方案。密码、验证码类字段不会发送。
2. **扩展的「深度分析本页」**：只在你点击、并在第一次使用时同意后才发送。扩展先在本机把当前页面整理成结构大纲（控件类型、字段名、分组标题、按钮和提示文字，每段最多 40 字），交给桌面程序发往你设为「强模型」的服务商（没设强模型时用「当前使用」）。大纲不包含输入框里已有的内容；密码、验证码类字段整体跳过；手机号、邮箱、证件号、网址、像密钥的文字以及与你简历内容相同的文字，发送前替换为「〔内容〕」。分析之后的填写匹配与「AI 填写」相同，会发送字段说明和相关简历片段。分析结果只在当前页面的内存里使用，不保存、不上传。AI 判断需要先点「编辑」「展开」或「添加」时，侧栏先列出要点的按钮，你确认后扩展才在当前页面点击，点完后在本机重新生成大纲、按同样的脱敏规则再分析一次（与填写匹配合计每次最多 6 次请求）；新增几条由扩展按你的简历模板计算。扩展不会点击提交、保存、删除、下一步或离开当前页面的链接，也不会替你保存或提交表单。
3. **扩展的「保存岗位到桌面端」**：本地认不全公司或岗位时，扩展把页面上几段相关文字（公司名称、职位标题、页面标题这类，最多 8 段，每段不超过 160 字）交给桌面程序，由桌面发给你选为「当前使用」的接口识别。不发送整页、表单里填的内容、简历或网页链接。识别出的结果要你在表单里确认后才保存。
4. **桌面的「AI 解析简历」**：在桌面「简历」页选择 PDF、DOCX 或 TXT 简历并确认后，桌面先在本机提取文字，再把整份简历文字发送到你配置的 AI 接口，以生成结构化模板。这些文字可能包含姓名、联系方式、教育和工作经历等信息；原始文件本身不会随这个请求上传。发送前会显示发往哪个服务商和字数。
5. **桌面的「AI 整理」**：把你导入的那封通知的正文，和最多 8 条候选申请的**公司名、岗位名、当前阶段**，发给你在桌面设置里填的那个接口。发送前会把要发的内容摆给你看，点了「发送」才发。

桌面发出的 AI 请求会带上软件名称和版本（User-Agent）。如果你用的是 OpenCode，请求还会带一个每次启动随机生成的会话编号，这是 OpenCode 的要求，编号不含你的任何信息。

这些功能都有同一件事要说清楚：**接口是你自己配的，数据会到那家服务商手里，他们可能留存。** 我们既不代理、也看不到这些请求。请求使用你配置的 API Key 向该接口认证。不配置 AI 时，仍可导入 Excel 模板、手动填写和使用本地岗位管理；AI 填写、保存岗位时的识别、AI 简历解析和 AI 整理不可用。

桌面程序还会在你允许的情况下去 GitHub 查一次「有没有新版本」。这个请求不带账号标识，但和任何网络请求一样会让服务器看到常规的 IP / User-Agent 元数据；它只查版本，可以在设置里关掉。

## 错误报告与手动反馈

我们在用户群和社交平台上收到的反馈，很多只有一句「填不上」「用不了」，看不出是哪个网站、卡在哪一步，很难找到原因。自动错误报告用来补上这部分信息：插件或桌面程序出错、一键填写有字段没填上时，把当时的技术情况发给我们。它只用于定位和修复问题、改进填写兼容性。

自动错误报告要你同意后才开启。插件安装或更新到包含此功能的版本后，会自动打开状态页显示说明（之后打开侧栏也会显示，直到你作出选择），写明报告内容、用途、接收方、随机安装编号、可能公开到 GitHub 的范围和关闭方法，并给出“同意并开启”“暂不开启”两个选项；桌面第一次打开时弹出同样的选择。你选择之前不发送任何自动报告，关掉侧栏或不选都不算同意，下次打开还会询问。同意之前出的错不会保存，同意后也不会补发。

之后可以在插件状态页的“开启自动错误报告”、桌面“设置 → 隐私”里随时更改。关闭后不再发送新报告，正在发送的请求会尽量取消（已经送达的不受影响），并删除该端的随机安装编号，不影响正常使用和手动反馈。插件与桌面分别设置，不同步。早期测试版默认开启，“知道了”只收起说明，所以从测试版升级时，旧版留下的开启状态不算同意，会重新询问；明确关闭的选择保留。设置读取或保存失败时不自动发送。

桌面通过本机 Rust 进程发送，捕获 webview、React 界面异常和 Rust panic；panic 上报尽力完成，进程直接终止时无法保证送达。

自动代码异常报告含错误类别、筛选后的本程序代码位置、版本、系统、发送时间和随机安装编号，不发送任意异常原文（原文可能含用户内容）。网页内容脚本仅报告堆栈属于本扩展的错误，并附出错页 hostname，不含路径、参数、浏览记录；网站自身异常不上报。

普通一键填写扫描到 0 个字段、有匹配字段没填上或提示“先点编辑”时，附上填写诊断：计数、耗时、错误类别和失败阶段、域名、网址路径（只保留 apply、resume、campus 这类常见路由词，其余段一律替换为占位符，不含查询参数和锚点）、是否判断为网申填写页及判断依据、控件结构和进一步筛选的字段名。判断为不是网申填写页的空页面、取消、拒绝覆盖、辅助新增、深度分析和全部填上不触发。禁止发送简历、字段值、页面标题和正文、完整网址、Cookie、API Key、AI 请求或响应正文。

不启用自动报告也能“手动反馈问题”。描述先清洗邮箱、电话、长数字串、网址、凭据和用户目录，诊断默认勾选且可取消。发送前完整预览实际报告。自动规则无法判断任意自然语言是否含私人信息，请勿在描述中填写姓名、简历、账号或密钥，核对后再确认发送。

同一错误或同一网站同类填写失败 24 小时最多自动发送一次；每台设备每小时最多发送 5 条代码异常报告和 20 条填写类报告，两者分开计算；429/5xx 后暂停自动发送一小时。请求 5 秒超时，不做离线队列或自动重试；失败的自动发送也占用当日该错误的去重名额。手动反馈至少间隔 60 秒，明确显示成功或失败。

报告发往 `https://app-feedback-relay.nebula-lab.workers.dev/feedback`。错误报告会暂存在我们的数据中转服务中，最长保留 90 天，到期自动删除；上报的 IP 地址仅用于防滥用。Muse 整理后的报告可能公开出现在本项目 GitHub Issues，包括版本、系统、发送时间、错误类型、网站域名和诊断内容，用于复现；公开的 issue 不随中转的 90 天删除。随机安装编号和 IP 只留在中转里，不写进公开 issue。

本机保存你的选择、随机安装编号、节流时间和错误特征哈希，不持久化自动报告正文。安装编号只在你同意后生成，关闭即删除；手动报告每次使用新生成的随机编号，不要求开启自动报告。

## 使用数量统计

使用统计仅用于了解软件的下载和活跃安装数量，帮助判断维护哪些版本及系统。它与错误报告完全独立，不沿用错误报告的随机编号或同意选择，数据也不会进入 Muse 或公开 GitHub issue。

在桌面“设置 → 隐私”可以更改“分享使用数量统计”。无旧选择的安装默认开启；关闭选择在重启和升级后保留。首次发送前，主窗口显著显示用途、发送字段、接收方、保留期限及关闭入口；在点击“知道了，保持开启”前不生成统计编号、不发送、不缓存或补发之前的活动。该按钮记录已查看说明，默认开启不作为用户主动同意的证据；正式发布仍须核对适用商店的告知及同意要求。

desktop 来源仅在主动打开或聚焦可见桌面主窗口、或在该窗口主动操作时才可能发送；extension 来源由已连接桌面程序的插件侧栏或状态页中的可信、可见主动输入触发，不要求桌面主窗口可见。隐藏启动、后台保活、更新检查、同步、提醒任务、握手和错误报告不触发使用统计。每个 UTC 日（北京时间上午 8 点切换日期）每种来源最多尝试一次请求，失败也占用当天额度。请求异步执行，3 秒超时，不跟随重定向、不自动重试，无心跳或离线补传队列，统计失败不影响填写和档案功能。

活动请求仅包含协议版本、独立随机 UUIDv4 安装编号、桌面程序版本、Windows/macOS 系统类型及 desktop/extension 来源。不发送简历、姓名、联系方式、申请内容、网页域名/路径、页面标题、具体操作、浏览器标识、设备指纹、AI 内容、API Key、Cookie 或错误报告编号。随机编号可以关联同一个安装的活动，因此属于假名化标识，不能称为完全匿名的数据。

接收方为我们管理的 Cloudflare Workers + D1 统计服务；正式接收地址为 `https://resume-usage-metrics.nebula-lab.workers.dev/v1/activity`。开发、测试、普通 CI 和未配置正式门禁的构建不发送使用统计。Cloudflare 按常规网络处理 IP 等 HTTP 元数据；业务数据库不存原始安装编号、IP、完整 User-Agent 或请求正文，业务日志不记录编号或正文。服务使用独立密钥计算编号的 HMAC 后用于去重。

插件仅在可见侧栏或状态页接收到浏览器可信主动输入时通知桌面，不统计初始化、预取、握手、同步或后台唤醒。通知的负载为空，不含网页、字段内容或浏览器标识。旧桌面不支持时忽略，不弹出错误、不重试、不持久排队。统计信号不会拉起已退出的桌面。Chrome、Edge 与桌面使用同一桌面统计编号，两个来源各每天最多一次，云端合并为一个活跃安装。新增插件来源需重新查看版本 2 告知；已关闭选择继续保留。


带安装标识的活动明细保留 45 天；不含安装标识的数值汇总和公开下载快照保留 365 天。日、周、月活跃数只代表“已启用统计且成功上报的活跃安装样本”，不是全部人数；下载次数也不等于安装或使用人数。

关闭立即停止新活动请求并尽力取消在途请求，清除本机编号和尝试日期，持久保留关闭选择。仅在内存短暂保留旧编号，尝试一次云端 DELETE 删除对应明细，3 秒超时；关闭不等待云端结果，删除失败不自动重试，也不声称即时删除成功。云端为阻止晚到请求，短期保留编号 HMAC 的撤销记录，最多 45 天；重复删除不延长期限。已生成的无标识汇总不随删除重新计算。Cloudflare D1 的受管恢复副本按账户方案最多保留 30 天，因此在线明细删除不代表所有恢复副本立即消失；恢复后必须先清理过期数据并保留撤销记录，避免已经删除或退出的活动重新出现。

再次手动开启时，下一次满足条件的主动使用才生成新编号，不补发关闭期间活动。统计状态损坏、丢失（初始化标记仍存在）、无法可靠读写时停止发送；无法保存关闭选择时，界面会说明本次运行已停发及需要处理的磁盘问题，不保证无法写入的选择能跨重启保存。

## 不会发生的事

- 不向反馈中转上传你的简历、申请记录或附件。
- 不做用户画像、具体操作轨迹分析或广告追踪，不引入第三方埋点 SDK；使用数量统计仅按上述最小字段和规则处理。
- 内容脚本会在所有网站注入，用来在本地判断当前页是不是网申表单；判断只在你的浏览器里做，不上传页面内容。只有你主动使用填写功能时，才会读写当前页的表单字段。
- 扩展用 `tabs` 识别当前标签页，并向该页的内容脚本发送用户触发的填表操作；也会查询扩展自己的状态页 URL 以复用已打开的标签页。不读取浏览器的历史记录；开启自动错误报告后，报告里会有出错网页的域名和筛选后的路径，见上文。
- 扩展对用户数据的使用遵守 Chrome 应用商店的[有限使用（Limited Use）要求](https://developer.chrome.com/docs/webstore/program-policies/limited-use)：只用于本文写明的功能，不出售，不转给与这些功能无关的第三方，不用于广告或判断信用。
- 扩展不持有 AI Key，也不直接连接任何 AI 服务商；桌面程序不会把 Key 回传给扩展。唯一的例外是上面说的一次性旧数据迁移：旧 Key 从扩展交给桌面，存进系统凭据库。

## 权限为什么要这些

| 权限 | 用来做什么 |
| --- | --- |
| `<all_urls>` 的 host 权限与内容脚本 | 网申页面遍布各家公司自己的域名，事先列不出来。内容脚本会在所有网站注入并在本地判断当前页是否为表单；只有你主动使用填写功能时才读写当前页字段 |
| `tabs` | 识别当前标签页，并查找、复用本扩展状态页；侧栏通过扩展消息向当前页内容脚本发送用户触发的填表操作，不读取浏览器历史记录 |
| `sidePanel` | 在 Chrome / Edge 浏览器边缘显示填表助手；侧栏通过扩展消息与当前网页的内容脚本协作 |
| `storage` | 存侧栏界面状态、与桌面的待同步队列、填写留档去重记录、旧数据迁移状态，以及错误报告的选择、随机安装编号与节流记录 |
| `nativeMessaging` | 和桌面程序通信：读取简历、写回「我的信息」、转发 AI 请求、保存岗位与投递记录。host 清单里只写了本扩展的 ID，别的扩展启动不了它 |
| `offscreen` | 在离屏文档中运行随包提供的 Worker，组装用户主动触发的 AI 填写、AI 辅助新增条目、深度分析本页和保存岗位时识别的提示词并校验结果；请求本身交给桌面程序发出 |
| `alarms` | 安排与桌面程序离线补传、旧数据迁移状态查询的重试 |
