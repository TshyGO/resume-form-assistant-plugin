# D15 手动云备份闭环与验收记录（#306）

## 实现与边界

- 从 `92610c5d6e1829117630c9298e43bd120b095709`（#309 / #305 合并结果）开分支。候选 SHA 以本 PR 当前 head 与对应 CI run 为准；本文件随候选提交，不以自己的提交哈希作循环引用。
- 设置页提供非秘密配置、只写凭据、只读连接测试、手动备份/取消/重试/放弃、时间与明文路径、来源设备发现、轻量列表，以及下载校验→对比→确认替换。默认 age 加密，关闭前必须明确确认。
- 生产恢复命令为 `cloud_backup_preview` / `cloud_backup_restore(token)`；替代 #305 初期的路径式 `cloud_backup_download` IPC。前端不能通过云恢复接口传任意文件路径。
- 发现最多 64 个档案目录、累计 128 个来源设备；每个设备的列表继续使用 #305 的月份/条目上限。列表不读包正文，不授予删除权；服务器完整性未经真实验收，清理继续关闭。
- 后台持有独立工作目录、已校验文件、SHA-256 和随机单次令牌。十分钟到期主动清理；取消、新选择、失败、重启均失效。确认前后复核文件哈希，准备隔离恢复后再调用已有可靠切换与回滚路径。
- 任意恢复/回滚前持久化关闭自动云备份并要求重新确认。配置和浏览器配对共用 host mutex；配对编辑合并保留 cloudBackup。设置写失败拒绝激活。#307 必须尊重 `automaticEnabled` 与 `requiresConfirmation`，不得从备份恢复调度开关或设备身份。

## 首轮审核修正

- 部分档案目录权限/读取失败时保留其他可用来源，并显示警告；取消仍立即向上返回，不把取消伪装成部分成功。
- 恢复返回 `RestoreOutcome { report, cleanupWarning }`。明确关闭后台任务目录并检查删除结果；清理失败不把已经激活成功的档案报告成恢复失败。Windows 使用实际独占文件句柄制造删除失败，验证成功 + 警告，并在释放句柄后由启动清理移除残留。
- 前端清理 IPC 或刷新失败保留已恢复结果，并给出清理未确认/重新打开页面提示；新增第 6 个云界面回归通过。配置初始读取失败也显示错误，不默默呈现为未配置。
- 不采纳“HTTP 会发送凭据”“同 connectionId 会复用新账号的密码”：`cloud_settings::save` 在写盘前执行 `Binding::checked` 强制 HTTPS；Client 亦校验。凭据键同时包含连接 UUID、规范化 HTTPS 端点及账号 SHA-256 指纹，原凭据不跨绑定复用。
- `HostPaths.settings_file` 始终是验证过的数据根目录下的 settings.json，parent unwrap 在当前构造不变量下不可达；不为假设路径更改主机错误契约。Windows 未承诺完整断电耐久性；#307 应在启动时重读并失败关闭，不能凭 UI 状态自动开启。进程退出与正常重启保证与突然掉电保证区分。

- CodeRabbit 的状态轮询失效、设置错误文案、接口表过时三项已修复；新增第 7 个云界面测试模拟状态读取失败后恢复，按钮不会永久禁用。
- C 路的三个疑问逐项核对：`restoreBody` 本来只展示文件名，云端包名正是正确来源说明，临时路径不必回传；既有配对 IPC 已在 `lib.rs::save_pairing_draft` 持有同一 `state.host` 锁，云配置读写与 suspend 也持有该锁；凭据失败后的清空是有意减少秘密驻留，错误明确说非秘密配置已保存、哪些凭据未完整保存需重输，不放行未完成配置。
