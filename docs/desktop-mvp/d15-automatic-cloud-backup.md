## 时间与执行

- 计划启用必须有当前连接摘要、远端根目录、明文/加密策略、archiveId、restoreEpoch 对应的成功手动备份基线，且凭据存在；初次默认手动。
- 用户确认执行时间、每 1–30 天频率（界面提供每天/每 3 天/每周）、固定 UTC 偏移。首次取下一个所选时间，此后固定日期间隔；时区不是隐含系统状态，不自动跟随旅行或夏令时。需要跟随新时区须主动重新确认。后端不依赖多线程环境下可能取不到的系统本地偏移。
- Tauri setup 完成后后台每约 30 秒检查，隐藏到托盘仍运行，无 OS 任务、额外服务或网页调度器。程序退出后不执行。时钟回退暂停；睡眠/重开导致槽位逾期超过两分钟或检查间隔超过两分钟，推进到下一未来槽位并提示手动补备份，不立即补跑。
- 时钟在可能等待的 store/journal 读取之后重新取值，避免长时间等待后用旧时间启动已错过的槽位。槽位 claim 和候选 ID/重试时间先原子落盘再启动，重复 tick 不创建重复作业。Service 的同一 lease 与手动上传/浏览/恢复互斥。正常退出发取消，若来不及完成安全收尾，重开将非终态标为 Interrupted，计划暂停等待人工处理，不自动补传。
- 恢复、回滚先持久化关闭 settings 开关并取消自动任务；执行前和打包时检查身份绑定。编辑连接/策略也关闭计划。暂停不阻止手动上传或重试。

## 内容指纹 v1

从同一 SQLite backup API 快照读取逻辑状态，按表名、列名、值类型、有序行和长度前缀流式计算 SHA-256。不是 SQLite 文件字节，也不是包哈希。新表默认纳入，避免新增业务后静默漏备份。

纳入申请、事件、证据、引用、已完成快照、待办、AI 决策、简历模板/状态、导入状态、业务时间、序号、持久回执及删除墓碑；后几项影响恢复后的幂等/去重，保守纳入。排除迁移执行时间、上传中的快照临时块、OS 提醒投递句柄/状态，以及待办中会被提醒登记刷新、与业务编辑混用的 updated_at；待办真实字段/状态和对应业务事件仍参与。数据库外纳入打包器已校验的附件/快照实际摘要、meta.json 及白名单可迁移设置。文件引用缺失或内容不符会失败，绝不当作未变化跳过。

包的 createdAt、随机备份 ID、ZIP 元数据、SQLite 页布局、age 随机盐/密文均不参与。作业自身保留本次快照指纹，只在远端元数据提交确认后更新成功基线；失败不推进。自动作业指纹相同标记 Skipped，跳过 KDF 与网络；手动作业始终允许重新生成/上传。当前为验证实际引用字节仍生成 ZIP 后判断，后续可独立优化打包成本。

## 重试、流量和预算

- 连接/超时/限流/5xx 上层最多自动重试 3 次，基本 60/120/240 秒，加上调度检查粒度，至少等待已观测 Retry-After 的 UTC 截止时间。传输层自身已有最多两次只读重试；所有重试均有界。异常巨大等待时间暂停，不能把它截短后提前重试。
- 使用已有候选 ID/密文字节，不重新 KDF。未知 PUT/MOVE/元数据结果沿 #305 先 HEAD/读取/下载完整哈希对账，再决定是否需要上传。已确认成功、清理警告均终结上传，不重传。认证、权限、空间、大小、预算、冲突、取消及中断需手动处理。
- 首次成功包提供最近大小，估算 `size × ceil(30/everyDays)`，并明确内容变化/重试会改变用量；没有包即不可用，不虚构余额。官方免费参考为上传 1 GB、下载 3 GB/月，重置不一定是自然月：[坚果云流量规则](https://help.jianguoyun.com/?p=29)，2026-10-19 核对。
- 本机周期从第一次 PUT 尝试起连续 30 天，不冒充账号账期。每次实际包体/元数据 PUT 前预记完整字节，失败/丢响应不返还；对账已存在则不再计一次包上传。手动尝试也计入，但不因自动预算暂停被阻止。重新启用不清零周期。80% 提醒，超出预算默认暂停，可明确选择仅提醒。探测、HTTP 开销、对账下载和其他客户端不在计数内。

### 第一轮审核修正

- macOS CI 暴露 UTC 主机上的 JS `-0`/`0` 测试断言差异，规范化期望后以 `TZ=UTC` 实跑云界面 11 项通过；运行参数实际一直为正确的 0。
- 调大预算重新启用时按新阈值重算警告而保留周期/已计字节，兼容带 CLOUD_ 前缀暂停码，缺失失败码给出明确回退；新云模块共 33 项通过。
- 提醒登记会同步改待办 updated_at，指纹因此排除这个混用的记账时间；真实待办字段和业务事件继续触发，回归已覆盖。
- 既有 poll 本来已清除旧 timer，另外增加并发请求合并，避免两个在途刷新各自排新 timer。
- 未接受没有实际触发路径的疑点：manifest 在 writer 中已按 path 排序；meta.json 来自档案原文件，createdAt 为档案创建时间，包时间只进 manifest；失败发生在已发布之后时 finish 保留 published 并转清理警告，而不提供重传入口；todos schema 保留业务主键等列，不会全被过滤。
- 元数据阶段预算不足的 intent 是保守的持久写入意图，并非已上传证明，仍先对账。补充实测元数据暂停→手动重试只上传一次包体，以及发布后 state.json 写失败仍无重传入口。


### 第二轮审核修正

自动检查在读取/决定/提交槽位之前先持有同一个 Service operation lease，避免与手动开始/重试之间的竞争误暂停，也防止旧策略快照覆盖同时变化的预算状态；已经忙时不消费槽位，后续按两分钟窗口正常检查或提示错过。忙期间也检查系统时钟回退。新增回归验证忙时不 claim、不误暂停及回退时暂停，云模块 34 项通过；界面移除对异常缺失计划的非空断言并显示重新确认提示。

低置信度的 Relaxed 原子序建议未采用：这里共享的是单个原子最大值，没有通过它发布其他内存；同一备份客户端的请求顺序执行，结束后读取其已观测值，跨任务 await/完成边界亦有同步。不会因使用 Relaxed 而丢失单个 fetch_max 更新；其余 schema 假设性空列建议仍无实际触发路径。


### 第三轮审核修正

B 路有效意见集中处理：内部 SQLite 表改用精确 `sqlite_` 前缀匹配，避免 LIKE 的 `_` 通配符漏掉 sqlitex 等未来业务表，回归已覆盖；普通本地导出走不计算云指纹的共享打包路径，保持原性能/失败边界；调度 tick 或 worker 错误记录安全错误码、在可写时持久暂停（写失败时仅内存可见回退），相同连续错误不重复写日志，前端状态读取失败显示全局处理提示。主程序最新本地回归 **452 passed、2 ignored、1 filtered**，云模块 34 项，指纹回归与 UI 11 项通过。

不接受将损坏 automatic 段静默丢弃的建议：此文件同时承载候选、已发布状态、预算和删除授权证据，结构校验失败继续保留文件并关闭云服务，避免猜测式修复；正常暂停不阻止手动操作，损坏日志也不阻断普通本地备份或其他业务。持续 30 秒状态刷新支持后台启动任务和全局错过/错误提示，只做本机 IPC，无网络轮询；事件化/可见性节能优化可独立跟进。C 路已通过同模型备用供应商产生有效审核；其未定位的 KDF 疑点经 prepare 的提前返回确认不成立。


### 凭据边界收尾

采纳最终 B 路的口令变更与锁持有意见：凭据变更先持久关闭自动开关；更换/移除备份口令还清空基线并将已有候选标记 fingerprintStale，之后旧候选即使完成发布也不能重新建立基线。新的手动包才能使计划再次启用，已有密文/重试候选仍需原口令，界面与帮助明确说明。使用独立凭据互斥锁将“读取凭据→创建候选”与凭据写入串行，覆盖读取旧口令后才创建新候选的竞争。

后台在读取系统凭据前释放 host 锁，读完后再次核对持久开关、配置、取消令牌及档案身份；期间用户可编辑设置/恢复，过期作业不会启动网络。保守的本机读写失败暂停保留：不把未知配置读失败当作继续上传的依据，已有全局提示/日志且可明确重新确认，不增加自动无限重试。


### 隔离包补证与隐私删除边界

3af0573 的双平台功能 CI、隔离包和三路 AI 证据已通过。其 Windows 隔离包已核对 build-receipt 候选与 SHA-256，并以真实 Tauri IPC + 系统凭据库验证：默认关闭、合成凭据保存/存在、不具备成功手动基线时返回 CLOUD_MANUAL_BACKUP_REQUIRED 且不开计划、凭据删除后两种存在状态均为 false。生成值只在内存传递，未访问真实账号、未上传；随后正常退出。此证据不代替 #306 的真实坚果云与物理双平台验收。

CodeRabbit 的一条实际隐私回归已修：云日志/工作区不可用或 settings 异常时，删除凭据仍调用系统凭据库；服务可用时仍持独立凭据锁、尽力暂停和失效基线，异常时使用可见暂停回退。**写入新口令继续严格要求持久基线失效**，不能照建议在服务缺失时直接换口令而遗留可重新启用的旧基线。缺少秘密无法重新开始上传，重启后的未知/中断候选仍需手动确认；新增回归验证服务/设置失败不拦删除且保留真实凭据库错误。
