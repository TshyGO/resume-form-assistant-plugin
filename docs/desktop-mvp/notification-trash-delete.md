# 招聘通知回收站：永久删除

## 行为

此前通知只有可恢复回收。本次在「招聘通知 → 回收站」的单条详情加入“永久删除”，复用现有应用内危险操作弹窗，默认聚焦取消。展示通知标题、正文／关联／AI 建议删除范围，以及原件和内嵌附件仅在无人共用时清理的规则。取消不写入，执行中禁止连点，失败保留弹窗供重试。

只删除通知，保留申请、已生成的进度和待办；不删除邮箱服务器邮件、已有备份和用户另存副本。不提供批量清空。

## 数据一致性

- 无数据库结构迁移。存储层要求通知仍在回收站且原件摘要匹配，通知、AI 建议、回收标记、引用计数和最小回执墓碑在同一事务更新。历史操作保留无正文的永久删除事件，不回退申请阶段。
- 确认预览绑定当前 archiveId／restoreEpoch／通知 ID／原件摘要。确认前恢复通知或切换档案会拒写；迟到的预览不能为另一条已选通知弹出确认。
- 邮件内嵌附件保存在同一 MIME 原件中，查看器按需解析，不另建附件子表；归档库中只有 `reply_evidence` 引用 `attachment_blobs`。系统打开的临时副本沿用既有缓存清理期限，用户另存副本保留。
- 引用数从实际证据行重新计算，包含其他回收通知。共用原件保留。只有零引用原件才删除文件，移除成功后清理 blob 元数据；失败保留零引用元数据，可由既有附件维护重试，并在界面提示部分清理未完成。
- 删除在宿主档案锁下执行，沿用备份／恢复互斥。附件相对路径受控，检查规范化父目录；目录符号链接指向档案外时拒绝清理。
- 同一已完成插件上传重试得到 PreviouslyPurged，不复活通知。用户重新发起的主动导入可以创建新通知。

## 验证边界

自动化覆盖取消／确认、双击锁定、删除失败重试、迟到预览、共用原件、部分清理提示，存储事务、摘要不匹配、恢复后拒写、跨档案／恢复 epoch、AI 建议清理、最小回执墓碑、内存上传回执重试、丢失文件及文件清理失败，Unix 目录符号链接越界保护。

本地手动验收与自动化测试分开记录。代码测试不代表用户已亲自验收；Windows 文件系统行为以 CI 和后续 Windows 手测为准。

本轮本地验证（2026-10-31，macOS）：archive-store 全套 136 项通过；原生应用 555 项通过、2 项已有忽略；React 426 项通过；纯界面逻辑 239 项通过；桌面类型检查、生产构建及独立测试应用构建通过。Rust 命令级使用已验证的 MacOSX26.5 SDK，HTTP 回环测试设置 NO_PROXY/no_proxy，未修改系统 SDK 或代理设置。

独立测试应用的现场检查使用新建合成文本通知，已检查移入回收站、新按钮、确认范围、默认取消焦点及取消后仍可恢复。最终永久删除在自动化临时档案中验证；用户手动验收尚未完成。正式应用和既有 Gmail 测试档案、Chrome／Edge 原注册保持原样。
