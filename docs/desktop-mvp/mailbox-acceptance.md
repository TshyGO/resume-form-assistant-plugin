## 2. 邮箱与入口矩阵

“原件”指完整 MIME，包含邮件内嵌附件；不包含附件中的网盘链接。“摘录”只保留页面可读文字，明确缺少原件与附件，不能保证与后来原件自动合并。网页保存仅由用户显式点击触发；IMAP 先发现信头，用户确认后才下载整封。

### E03：Gmail IMAP 登录前 TLS 阻塞，暂缓实测

2026-10-31，本轮主机运行独立 Dev358，基线 `38847f0`、源码版本字符串 0.4.4、Rust 1.94.0、Node 22.23.2，使用隔离档案。用户在本机提交应用专用密码后，配置未保存，返回 TLS 类别。

无凭据的独立探测复现：直接 TCP（系统 TUN 仍生效）与显式本机 SOCKS 均在 TLS 握手收到 EOF；限定 TLS 1.2 同样失败。与 App 相同的系统 TLS 库返回 `-9806 / connection closed via error`，QQ IMAP 993、Google HTTPS 443 对照通过。失败发生在 IMAP LOGIN 前，不能判定密码错误，也不能断言一定是代理节点故障。未关闭证书验证或修改系统代理。

维护者决定暂缓网络切换与真实 IMAP 验收，取消 Windows 测试包；没有产出或交付该包。后续需可用链路，再验证登录、发现与入档。公开记录不保留账号地址、目标主题、代理出口名、真实原件或密码。

同一基线自动检查：mailbox-sync 59 项、桌面邮箱命令／来源 33 项、邮箱界面 64 项及桌面类型检查通过；这些结果不记为真实 Gmail 通过，也不宣称本次仅改文档后重新运行了产品全套测试。
