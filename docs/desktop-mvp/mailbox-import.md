# #331 邮箱只读发现与确认入档

状态核对（2026-10-31）：#331 已随 PR #345 合入，issue 已关闭；以下历史记录仍未提供 QQ／163／126 的完整真实账号闭环，关闭状态不等于真实验收完成。当前支持、发布边界与补测清单统一见 [#358 邮箱验收矩阵](mailbox-acceptance.md)。下文保留各轮原始测试结果，不把旧结果标成最终候选通过。

## 行为与实现

- 第一版 QQ（含 foxmail.com 地址）、163、126 使用预设服务器与 TLS 993；#332 增加更多邮箱和可编辑的服务器配置，见 [学校邮箱接入说明](mailbox-school.md)。`async-imap` 0.12 支持 NetEase 登录后的 `ID`、只读 `EXAMINE`、UID 搜索与 `BODY.PEEK`。
- `mailbox-sync` crate 负责 IMAP、信头解码、本地筛选与机器状态库；`mailbox_commands.rs` 负责凭据、调度、档案身份检查与复用 `evidence_commands::import_bytes`。
- 启动检查一次；其后进程内每 30 秒判断是否到期，成功后 10 分钟再检查，失败依次等约 60、120 秒后重试，第三次失败暂停。恢复检查或更新授权码后重新检查；完全退出后没有 OS 定时任务。
- 每个档案、账号、文件夹保存 `UIDVALIDITY + 最后处理 UID`，首次或 UIDVALIDITY 变化用服务器收件日期回看最近 30 天。优先快照 UIDNEXT；163 / 126 的 Coremail 未返回 UIDNEXT 时，用只返回编号的 `UID SEARCH ALL` 取得最大 UID，再搜索有界区间，避免 `n:*` 反向区间重复读取最后一封旧信。每批至多 100 封，候选与该批进度同事务提交；网络中断不推进游标。单封超限信头记为不可读取；仍存活但本次缺失的信头单独记录，扫描继续向后，每轮最多即时或补偿重试 8 封、每封累计最多三次，仍失败时在设置页指向手动导入。
- 收件箱和通过 LIST 开放的垃圾邮件文件夹（`\\Junk`、常见中英文名称、modified UTF-7 编码或层级路径的末级名称）。不扫描已发送、草稿、自建业务文件夹。测试连接只要求 INBOX 可只读打开；各文件夹独立扫描时，INBOX 失败记为账号失败，可选垃圾邮件文件夹失败不挡住正常收件箱，但记为“部分完成”、一分钟后重试并在界面提示，不触发整个账号的连续失败暂停。
- 只取 From、Subject、Date、Message-ID，单个信头读取上限 64 KiB。规则为招聘系统域名、申请公司、标题关键词的并集；公司名只匹配主题和发件人显示名，英文公司名按词边界匹配，不与完整邮箱地址做任意子串匹配。入选理由明确显示。域名匹配按标签边界，避免 `mokahr.com.evil.test` 或 `notmokahr.com` 冒充名单。飞书还需发件人带招聘特征，避免将普通通知全部纳入。
- 未命中信不保存内容。候选信头、理由、邮箱位置与处理状态保存在数据根目录 `mailboxes.sqlite`，不进入档案；确认才下载原文，限制 25 MiB，先读取大小，再用 1 MiB `BODY.PEEK` 分块下载，每块最多等待 30 秒。同一账号的一批确认复用一个登录会话，断线后最多重连一次；重连仍失败时，同账号剩余候选统一保留待重试。核对 UIDVALIDITY 与信头指纹后才导入。不会自动关联、分类、改申请阶段或执行 AI 整理。
- 已有正式证据先按 #330 的 MailKey（Message-ID、发件人、发送时间）匹配；确认时再查一次。没有 ID 的邮件在下载后用原文字节摘要保证确认重试幂等，防止档案写入成功、候选状态更新失败后重复创建证据。
- 忽略标记用稳定信头指纹，跨文件夹重扫和 UIDVALIDITY 变化保留。没有 ID 且信头完全相同的异常邮件存在无法区分的限制。断开账号清除其机器状态与凭据，已入档证据保留。
- 授权码只存系统 `CredentialStore`，不同账号独立命名，不提供读取授权码的 IPC。测试连接成功才保存；数据库保存失败回滚原凭据。编译禁用 `log` 的 debug/trace，避免 IMAP 库的协议转储记录 LOGIN 或邮件原文。
- 网络不占用档案锁；扫描互斥只防止两个检查任务重叠，确认、忽略、暂停和断开不再等待后台网络扫描。完成后核对 archive ID 与 restore epoch。档案恢复不回滚机器邮箱状态，旧任务不能写进恢复后的档案。连接、候选、忽略、游标不随备份迁移；备份格式与正式档案 schema 无变化。

## 自动验证记录（2026-10-26，macOS）

新增及相关测试：32 个 mailbox-sync 用例、11 个宿主邮箱用例、24 个邮箱界面用例，均通过。前端回归 239 个纯逻辑用例通过；组件套件共 356 个用例，一次全量运行中有 1 个既有简历表单异步用例超时，单独重跑通过。类型检查及生产构建通过。覆盖协议命令、NetEase ID、Coremail 缺少 UIDNEXT 的回退、层级垃圾文件夹、连接必需/可选文件夹边界、首次 / 增量 / 重建、未命中不留存、原子游标、断线、有限逐封回退、超限信头隔离、存活信头三次重试、部分文件夹失败、分块下载、公司名误匹配负例、错误邮件身份、忽略实际计数、凭据回滚、导入幂等、恢复隔离、备份排除、全选同步及批次部分失败。

执行命令（在 `desktop/`）：

```sh
cargo test --manifest-path crates/mailbox-sync/Cargo.toml --locked
cargo test --manifest-path src-tauri/Cargo.toml --locked --lib mailbox_commands
npm run typecheck
npm run test:ui
npm run test:react
npm run build
```

本机默认 MacOSX27 SDK 与 linker 不兼容；Rust 验证仅在命令级选择 `SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk`，未修改系统配置。

桌面 Rust 全量回归运行了 495 个用例：485 通过、2 忽略、8 失败。失败集中在已有 AI HTTP / 遥测 HTTP 测试，表现为本机请求报文正文未被测试服务端完整读到、头部被改写、关闭端口返回 HTTP 502；本机系统 HTTP / SOCKS 代理已启用。对未修改基线 `d7d7331` 运行同 8 个用例，7 个同样失败，另 1 个通过，表明还存在时序不稳定；没有将这些失败标为通过，也没有修改代理或顺带改动 AI / 遥测实现。应在无该干扰的 CI 环境继续核对。

界面已用合成数据走查设置页、图文教程和待确认区；合成预览不证明真实邮箱连接可用。Windows 由现有双平台 CI 加入的 mailbox-sync 步骤验证，本机未执行 Windows 测试。
