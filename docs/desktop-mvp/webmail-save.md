# #333 插件侧栏保存当前邮件

状态：本地实现及下列自动验证已完成。**QQ 新版已于 2026-10-27 完成一封带附件邮件的真实账号走查；163 / 126 真实账号尚未验收，不能关闭 issue 或声称所有邮箱已验证。**

## 行为

- 在 HTTPS 的 QQ（`mail.qq.com` / `wx.mail.qq.com`）、163 / 126 邮箱页面，插件自己的侧栏提供「存进网申快填」。显示入口仅根据活动标签页 URL；不预读邮件来判断是否已打开，不往邮箱网页插按钮。在列表页点击时提示先打开一封邮件。
- 点击时读取单封打开的邮件。QQ 与网易适配集中在 `webmail.js`；同源邮件 iframe 可读取，跨域 iframe 跳过。QQ 新旧界面、网易不同版本的选择器与原件入口仍需真实账号验证。无法可靠识别或有多个打开的阅读窗格时拒绝猜测。
- 优先使用邮箱工具栏中的完整邮件下载链接。QQ 经典阅读页可按当前阅读 URL 中的邮件编号 / 会话参数构造固定下载端点；网易同源阅读页及正文 iframe 提供完整 `sid` / `mid` 时可构造固定原件下载端点。仅接受邮箱同源 HTTPS 的限定只读路径，拒绝带 `part` 的单附件链接；不执行网页给出的任意代码，不截取 Cookie，不尝试绕过登录。QQ 新版的菜单处理见下节。页面不提供可用位置时走摘录兜底。
- 原文下载使用已登录的同源会话，不跟随重定向，20 秒超时，流式检查 25 MiB 上限。登录页、错误 HTML 不算邮件原件；完整字节交给桌面再验证并保存。邮件内嵌附件保留在 MIME 原文里，不承诺独立解析 / 预览每一个附件，也不下载附件里的网盘链接。
- 拿不到原件时，侧栏展示邮件标题及“未保存原件及附件”的说明；只有再次点击「保存网页摘录」才发送发件人、标题、原显示时间和正文。原显示时间保留为文字，不把无法解析的日期冒充确定时间。摘录有独立标识，不伪造 Message-ID，不能保证与后续原件跨渠道去重。
- 可选输入公司名称查找现有申请，用户手选后关联；默认进入收件箱。不是自动识别公司、不是自动关联、分类或修改申请阶段，不调用 AI。
- 邮件传输不建立持久待同步队列。连接失败时如实提示未确认保存，可重新点击。页面切换清除未确认的摘录。

## 传输与归档

- 新增 `mail.import`，最低协议 v4。握手仍发 v2，支持范围 2–4；新能力只向声明支持 v4 的插件公布，旧插件不会因额外枚举值而握手失败。旧桌面可继续填写等原有功能，邮件保存提示升级。
- 复用快照的 `planChunks` / Base64 工具，每块 32 KiB、完整业务帧不超过 64 KiB。邮件最大 25 MiB / 800 块，与简历快照的 2 MiB / 128 块限制分别维护。
- 整次上传固定 archive ID / restore epoch / client / upload ID / 内容摘要 / 类型 / 目标申请。每块校验序号、长度、SHA-256，完整后再核总长度与摘要；所有块通过校验前不写文件、不建证据。档案恢复后旧身份被拒绝，不自动重绑。
- 未完成的块只在桌面进程内存中；全进程最多 4 个未完成上传、64 MiB 缓冲。超过 15 分钟的状态在下次邮件请求时清理；退出桌面进程即丢弃。成功后清空原文缓冲，仅保留有界、短期的结果回执以处理最后一块重试。不进入档案数据库或备份。
- `.eml` 复用 `evidence_commands::import_bytes` 与 #330 的邮件编号 + 发件人 + 发送时间去重；无编号原件的完全相同字节重试也复用既有记录。摘录按粘贴文本归档，标题、原文及预览明确标注。相同摘录字节重试不新建记录，但无法据此合并摘录和原件。
- 入档由用户亲手触发，直接进档案，不进入自动拉取的待确认区。选择申请时先验证申请仍存在且未回收。已在其他申请里的同封邮件不自动挪动。
- 桌面完成持久化后才回 `saved`，仅块确认不能显示成功；桌面通知列表随保存事件刷新。插件不保存包含 `sid` 等会话参数的邮箱地址，正文与原件不写日志、错误报告或统计，不经过产品服务器。

## QQ 新版原件入口修复（2026-10-27）

真实账号走查发现，新版 `wx.mail.qq.com/home/index` 在“更多操作”里提供“导出为 eml 文件”，原生动作同步调用 `window.open` 打开同源 `/read/readmail?func=3&mailid=…&sid=…`。旧适配仅支持经典 `/cgi-bin/readmail` 及静态链接，实际会产生零个原件候选地址，直接进入摘录兜底。此前模拟经典页面的测试未覆盖新版。

- 在新版页面加载一个专用 MAIN world 脚本，加载时仅安装事件监听，不读取信件或订阅浏览历史，不增加插件权限。只有侧栏明确保存请求才进行一次限定的原生“更多操作 → 导出为 eml 文件”。
- 原生导出点击的同步调用期间临时接管 `window.open`，验证同源、固定路径、`func=3` 和当前会话，取得当前邮件编号后立即还原；不新建下载标签页、不触发另一份文件下载。桥只返回编号，不返回登录会话值，也不遍历 React / 全局邮箱存储。
- 隔离内容脚本用当前页面会话构造该固定导出地址，继续使用原有大小上限、超时、邮件切换校验与完整邮件格式检查。页面脚本的回复仅按随机请求编号接收；失败继续由用户决定是否保存摘录。正文内伪造的菜单不能触发导出。
- 新增自动用例覆盖原生点击、准确原文字节、无额外弹窗 / 下载、其他域名 / 操作 / 会话拒绝、错误 HTML、切换邮件、正文伪造菜单与异常时还原 `window.open`。Node 22 完整插件回归 1611 项通过，类型检查与打包清单单元测试通过。
- **实际 QQ 新版验证通过**：使用用户当前测试通知保存成功，桌面原件 525,844 字节；与 QQ 自带菜单手动导出的 `.eml` SHA-256 完全相同。MIME 中 1 个附件，解码后 380,268 字节。再次从插件保存提示“已在档案中”，正式原件记录仍为 1 条。未将真实原件、邮件编号、会话值或附件提交到仓库。
- 本次真实走查仅覆盖该 QQ 新版账号、该测试通知及带附件保存 / 重复保存。网易真实账号、所有 QQ 页面变体与跨渠道 IMAP 真实走查仍待执行；不据此关闭 #333。
