# T5-macOS 提醒、钥匙串、恢复、升级卸载与独立填写

本清单使用 T4-macOS 的同一组候选字节，补真实 Apple Silicon 生命周期证据。自动化只能整理和校验报告；睡眠、重启、杀进程、跨次日等待、Gatekeeper、钥匙串、DMG 升级和移除 App 必须在实机执行。

## 前置条件

- Chrome 与 Edge 的 `macos-report-template.json` 副本均绑定同一候选，并完成生产注册预检。
- 当前账户已通过主机预检，浏览器使用隔离 Profile，数据仅含 `d14-v1` 合成内容。
- 候选是 `aarch64-apple-darwin` DMG；旧版和新版 DMG 均有来源、源码 commit、版本和 SHA-256。
- 当前候选是完整 ad-hoc 签名、未公证；批准引用及实际 Gatekeeper 体验已记录。不得把 ad-hoc 写成 Developer ID。
- `lifecycle/report.json` 的全部项目初始保持 `NOT_RUN`。

## 提醒与进程生命周期

分别验证关窗、主动退出、强制杀进程、睡眠唤醒、系统重启和跨次日真实等待。记录 macOS 通知与应用内待办两个结果，确认时区正确、无重复投递、不混淆关窗与退出，也没有未经承诺添加登录启动项。跨次日不得修改系统时钟。

## 钥匙串与真实服务

使用专用测试凭据验证 API Key 写入 macOS 钥匙串，且不进入档案、备份、日志、诊断导出、截图或网络附件。覆盖正常请求、断网、超时、取消、非法响应和提示注入；正式字段仍只能在用户确认后变化。报告只记录提供商、模型、时间、样本逻辑 ID 和结果，不记录 Key。

## 备份、重复恢复与故障

1. 导出备份，核对清单、附件、快照和 SHA-256。
2. 恢复到新的合成档案根，再恢复同一备份；每次产生新的 `restoreEpoch`，业务顺序保持稳定。
3. 保留带旧 epoch 消息的插件 Profile，恢复后只允许暂停和对账，不自动重放。
4. 使用专用 APFS 测试卷或稀疏磁盘映像制造磁盘满；不得填满日常系统盘。失败时旧档案和 `current` 指针不变，卷外没有新增文件。
5. 分别验证损坏 ZIP 和路径穿越包被拒绝。

## 升级、移除与重装

1. 用可追溯旧 DMG 创建合成档案并保存升级前快照。
2. 安装当前候选，核对数据、附件、快照、待办、钥匙串引用和 Native Messaging 注册。
3. 对兼容和不兼容插件分别验证；不兼容协议必须有可诊断错误且无业务写入。
4. 从 `/Applications` 移除 App，确认 `~/Library/Application Support/ResumePro` 未被自动删除。
5. 记录 Native Messaging 清单在 App 缺失时的实际状态和浏览器错误；不得把残留的无效路径写成“已清理”。
6. 使用原候选插件完成独立填写，确认未安装/未配对状态不会建立长期离线队列。
7. 重新安装同一候选，确认生产注册自愈并重新连接原合成档案。

## 完成标准

`t5-macos-report-template.json` 的 16 项检查全部 `PASS` 且各有非空证据，审阅人、审阅时间和决定齐全，没有阻断缺陷。钥匙串与真实 AI 走查作为 D11 的独立证据记录，不额外塞进这 16 项。Mac 完成后仍写 `overallD14Status=PARTIAL_PLATFORM_ACCEPTANCE`、`windowsStatus=NOT_RUN`；Windows x64 后续验收完成前不能关闭 D14。
