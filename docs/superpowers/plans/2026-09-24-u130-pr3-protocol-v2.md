## 协议 v2 契约（PR 3a 落地，PR 3b / PR 4 照此实现）

### 版本

- `rules.json`：`protocolVersion: 2`、`minProtocolVersion: 1`、`maxProtocolVersion: 2`。新增字段 `"v2MessageTypes": ["resume.read", "resume.update", "ai.complete", "ui.open", "legacy.import"]`。
- 规则：**v2 消息的信封 `protocolVersion` 必须 ≥ 2**，否则 `protocol_incompatible`。v1 的 8 类消息在 v1、v2 信封里都照旧接受。
- 桌面响应的 `protocolVersion` 回显请求的版本（v1 请求得到 v1 响应，旧插件不受影响）。
- 握手：桌面宣告 `min 1 / max 2`。旧插件（max 1）握手求交集仍成功；新插件（PR 4 起 min 2）遇到只支持 v1 的旧桌面，交集为空 → `protocol_incompatible` → 插件提示「请更新桌面」。

### 身份与写入分类

| messageType | 信封身份（archiveId + restoreEpoch） | 算不算 `writeTypes`（走 message_receipts 幂等表） |
| --- | --- | --- |
| `resume.read` | 必须 | 否（只读） |
| `resume.update` | 必须 | 否（自身幂等：切换模板天然幂等；保存档案靠版本号） |
| `ai.complete` | 禁止（同 health） | 否 |
| `ui.open` | 禁止 | 否 |
| `legacy.import` | 必须 | 否（自身以 `(importId, index)` + 摘要幂等，见下） |

`identityRequired` / `identityForbidden` 相应追加；`writeTypes` 不变。

### 1. `resume.read`

请求 payload：`{}`（`additionalProperties: false`）。

响应 payload（`schemas/responses/resume-read.json`）：

```json
{
  "type": "object", "additionalProperties": false,
  "required": ["templates", "activeTemplate", "profile", "profileRevision"],
  "properties": {
    "templates": { "type": "array", "maxItems": 25, "items": {
      "type": "object", "additionalProperties": false, "required": ["id", "name", "fieldCount"],
      "properties": {
        "id": { "type": "string", "pattern": "<UUID>" },
        "name": { "type": "string", "minLength": 1, "maxLength": 100 },
        "fieldCount": { "type": "integer", "minimum": 0 }
      } } },
    "activeTemplate": { "oneOf": [ { "type": "null" }, { "$ref": "#/$defs/template" } ] },
    "profile": { "$ref": "#/$defs/profile" },
    "profileRevision": { "type": "integer", "minimum": 0 }
  },
  "$defs": {
    "template": { "type": "object", "additionalProperties": false, "required": ["id", "name", "groups"],
      "properties": {
        "id": { "type": "string", "pattern": "<UUID>" },
        "name": { "type": "string", "minLength": 1, "maxLength": 100 },
        "groups": { "type": "array", "items": { "type": "object", "additionalProperties": false,
          "required": ["name", "fields"],
          "properties": {
            "name": { "type": "string", "minLength": 1 },
            "fields": { "type": "array", "items": { "type": "object", "additionalProperties": false,
              "required": ["key", "value"],
              "properties": { "key": { "type": "string", "minLength": 1 }, "value": { "type": "string" } } } } } } } } },
    "profile": { "type": "object", "additionalProperties": false, "required": ["values", "family", "custom"],
      "properties": {
        "values": { "type": "object", "additionalProperties": { "type": "string" } },
        "family": { "type": "array", "items": { "type": "object", "additionalProperties": { "type": "string" } } },
        "custom": { "type": "array", "maxItems": 200, "items": { "type": "object", "additionalProperties": false,
          "required": ["key", "value"], "properties": { "key": { "type": "string" }, "value": { "type": "string" } } } } } }
  }
}
```

（`<UUID>` 用 envelope 里现成的 UUID pattern。`schema_lite` 若不支持 `$ref` / `oneOf` / `$defs`，**先看 `src/schema_lite.rs` 与 `js/schema-lite.mjs` 支持的关键字**，不支持就把引用展开写平、把 `oneOf [null, template]` 改为 `type: ["object", "null"]` 加业务校验；不要为此扩充 schema-lite 的能力，除非两边都能加上且有测试。）

整个响应信封 ≤ 64 KiB。桌面在序列化后校验字节数，超出返回 `payload_too_large`，**不截断**。

### 2. `resume.update`

请求 payload（二选一）：

```json
{ "op": "setActiveTemplate", "templateId": "<UUID>" }
{ "op": "saveProfile", "profile": { …同 resume.read 的 profile… }, "expectedRevision": 3 }
```

响应 payload：`{ "activeTemplateId": "<UUID>|null", "profileRevision": <int> }`。

错误：模板不存在 → `invalid_payload`；版本号对不上 → `conflict`（插件重新 `resume.read` 后再算一次）；档案形状/大小不合法 → `invalid_payload`；密码类内容 → `secret_forbidden`（协议层 Secrets 先拦英文的，桌面存储层再拦中文的）。

### 3. `ai.complete`

请求 payload：`{ "purpose": "fill" | "plan", "system": string (maxLength 8000), "user": string (maxLength 60000) }`。实际上限由 64 KiB 信封决定（中文约 2 万字），插件（PR 4）发送前自己检查字节数。

响应 payload（`ok: true` 时二选一）：

```json
{ "status": "ok", "text": "<模型返回的正文>" }
{ "status": "failed", "reason": "not_configured|auth|rate_limited|timeout|network|http|bad_response|input_too_large|response_too_large", "httpStatus": 500, "host": "api.deepseek.com" }
```

上游失败**不**用协议错误码表示（协议错误码是「这条消息本身有问题」），用 `status: failed` + 枚举原因，插件据此给出与现在一样具体的提示。`httpStatus`、`host` 可选；`host` 只是主机名。服务商的错误正文、Key、完整地址一律不出现在响应里。

Secrets：请求照常 `reject_secrets`——提示词里如果带着「password: xxx」这样的内容，本来就不该发给 AI。桌面生成响应前自己先跑一遍 `reject_secrets(text)`，命中就返回 `failed / bad_response`，而不是发出一个会被插件校验拒绝的响应。

### 4. `ui.open`

请求 payload：`{ "view": "resume" | "settings-ai" | "home" }`；响应 payload：`{ "opened": true }`。

### 5. `legacy.import`

请求 payload（按 `kind` 区分，统一带 `importId`）：

```json
{ "importId": "<UUID>", "kind": "manifest", "index": 0,
  "body": { "pluginVersion": "0.4.0", "total": 3,
            "parts": [ { "index": 1, "kind": "template", "sha256": "<64 hex>" },
                       { "index": 2, "kind": "profile",  "sha256": "<64 hex>" },
                       { "index": 3, "kind": "aiConfig", "sha256": "<64 hex>" } ] } }

{ "importId": "<UUID>", "kind": "template", "index": 1,
  "body": { "name": "校招简历", "wasActive": true, "groups": [ …同 resume.read 的 groups… ] } }

{ "importId": "<UUID>", "kind": "profile", "index": 2, "body": { …profile… } }

{ "importId": "<UUID>", "kind": "aiConfig", "index": 3,
  "body": { "apiUrl": "https://…", "model": "…", "apiKey": "sk-…" } }

{ "importId": "<UUID>", "kind": "status" }
```

- `total` 1..63（至多 25 个模板 + 1 档案 + 1 AI 配置，留余量），`index` 1..`total`，`parts` 覆盖 1..`total` 且每个 index 恰好一次。
- 每片 `sha256` = 该片 `body` 的规范化摘要，算法与 `payloadSha256` 相同（对象键排序的 compact UTF-8 JSON 的 SHA-256，复用 `src/digest.rs` 现有函数）。
- **Secrets 例外只有一处：** `kind == "aiConfig"` 时 `body.apiKey` 不参与 `reject_secrets`；`body` 里其他字段、其他 `kind` 照常扫描。任何其他消息里出现 `apiKey` 仍然 `secret_forbidden`。
- `aiConfig.apiUrl` 仍走现有 URL 凭据检查（userinfo、令牌参数）。

响应 payload：`{ "state": "receiving|awaiting_confirmation|imported|rejected|expired", "received": <int>, "total": <int> }`。

语义（PR 3b 实现，PR 3a 只定形状）：
- 同一 `(importId, index)` 重发、摘要相同 → 返回当前状态；摘要不同 → `conflict`。
- 已有另一个未结束（`receiving` / `awaiting_confirmation`）的 `importId` 时来了新的 → `conflict`，插件等待。
- 清单里每一片都到齐且摘要相符 → `awaiting_confirmation`（桌面界面弹窗由 PR 5 做）。
- 24 小时未收齐 → `expired`，整批作废。
- `kind: status` 只查询，不写入。
