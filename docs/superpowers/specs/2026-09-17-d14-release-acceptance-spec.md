## 1. 要交付什么

以同一组合成数据，在真实 Windows 普通用户环境，用实际安装包、实际插件 ZIP、Chrome 和 Edge，证明「保存岗位 → 填写留档 → 确认投递 → 导入通知 → 审核 AI 建议 → 待办提醒 → 备份恢复 → 升级卸载」形成可恢复、可追溯的闭环。最终发布的文件必须与验收文件一致。

D14 负责跨模块验收、证据归档与发布门禁。功能缺陷修复关联回对应模块；安装器与生产通信注册由 D13 实现。邮箱自动同步、云同步、Linux、额外安装器和商店上架操作不在本次默认范围。

## 4. 合成数据及结果判定

T1 提供版本化数据集 `d14-v1`，包含同公司两个岗位 A/B、另一公司岗位 C、模板 v1/v2、自动回执、测评邀请、ATS 自动面试邀请、模糊岗位通知、改期/取消、拒信、Offer 后补录的旧测评，以及恶意附件和错误模型响应。

使用虚构姓名、保留域名和可搜索的合成敏感标记。不得复制真实邮件、简历或用户档案。日期由运行基准时间和时区生成，记录基准；系统通知实测使用真实等待，不能以修改系统时钟代替次日提醒证据。

每个场景记录初始对象、动作及预期增量，至少验证：申请数、事件数及 `eventSequence`、附件引用与 SHA-256、快照内容/摘要、正式分类与阶段、待办时间/时区、outbox 与 IDB 状态。动态 UUID 用逻辑名称映射，不写死生产标识符。

备份/恢复比较的是业务内容、引用和事件顺序。`archiveId` 按契约保留，当前 `restoreEpoch` 每次成功恢复重新生成；不能要求恢复前后全目录逐字节相同。

## 5. 八条完整旅程

每条同时记录界面行为与可验证的数据结果。自动化调用内部方法可以辅助断言，但真实旅程需要实际用户入口。

| Case | 操作 | 必须成立的结果 |
| --- | --- | --- |
| J01 安装连接 | 干净普通 Windows 账户安装桌面与插件；Chrome、Edge 分别连接；覆盖先装插件/先装桌面及中文、空格路径 | Native Messaging 握手成功，实际 host 路径指向安装产物；生产 allowlist 精确；无意外终端弹窗；不依赖开发注册脚本 |
| J02 离线留档 | 已配对后使桌面服务确实不可用，保存 A、用 v1 填写并确认留档；随后改 v2、重启 SW/浏览器，再恢复桌面 | 离线显示待同步意图；上线绑定并只写入一次；历史仍为 v1；完整 ACK 前 IDB 原字节仍在。仅关窗口不算制造离线，因为 NM 可按需启动服务 |
| J03 投递与快照 | 填写完成后查看阶段，再明确确认已投递；修改当前模板 | 填写不自动产生已投递；明确操作才产生对应事件；历史快照不随当前模板改变 |
| J04 通知审核 | 导入合成回执/测评/面试，预览外发、分析、暂存、重启、修改、确认；重复确认 | 原件可回看；未分类文案正确；暂存分类保留；确认前正式字段不变；更新当前进度须单独选择；确认原子且幂等；ATS 面试不自动标成人工回复 |
| J05 多岗位消歧 | 同公司 A/B 收到模糊通知；人工选择 B 并修改建议；再分析同证据；Offer 后补录旧测评 | 不自动选 A 或 B；只更新获批准的对象；原模型建议、最终决定、原件、时间线均可追溯；旧测评默认只补历史，不回退 Offer |
| J06 提醒与恢复 | 建立待办，重启/休眠；备份后恢复新库，再次恢复同一备份，连接仍有旧消息的插件 | 待办恢复且时间正确；数据/附件/快照一致；相同时间戳事件顺序稳定；每次恢复新 epoch；旧消息暂停并对账，不自动重放 |
| J07 升级卸载 | 用可追溯旧版本建立相同数据，再装候选版；测试兼容和不兼容插件；默认卸载后重装 | 迁移前备份可用；原数据附件可读；不兼容有诊断且拒绝不安全写入；仅清理本应用所属注册；默认保留档案与备份 |
| J08 独立插件 | 卸载桌面后，在浏览器中继续使用插件模板和填写 | 正常填写可用；桌面不可用提示准确；未安装/从未配对不建立长期离线队列 |

## 6. 故障与反例覆盖

T3 先清点已有测试并登记对应名称；已有可靠断言直接引用，仅对缺口新增测试。

| Case | 注入/反例 | 核心断言 | 验证层 |
| --- | --- | --- | --- |
| F01 | 分片乱序、重复、ACK 丢失；在线传输中断/SW 重启/模板改变 | 每块持久身份不变；cursor 为连续 ACK 下一块；重传原字节；完整 ACK 前不删 IDB；快照和事件不重复 | 协议/link + 浏览器 |
| F02 | IDB 配额失败、outbox 索引丢失、原字节缺失 | 未持久化不宣称留档成功；可由 IDB 元数据修复索引；缺字节暂停且不从新模板伪造快照 | link/IDB |
| F03 | 桌面写事务失败或进程在提交边界崩溃 | 快照、事件、回执一致；未提交不返回成功；重试最多形成一次业务写入 | 数据层/进程 |
| F04 | 保存 ACK 丢失 → 永久删除 → 原消息重试 | 幂等墓碑有效，不重建已删除申请 | 数据层/link |
| F05 | 旧 epoch 回执对账；不同 Profile 相同 messageId；摘要冲突/缺失 | 历史回执可只读核实；不串记录、不自动执行冲突或缺失消息；旧队列不能靠改 epoch 解锁 | 协议/恢复/link |
| F06 | 同时间戳三个事件 → 备份 → 恢复两次 | `eventSequence` 顺序稳定，阶段折叠一致；两次新 epoch 不同 | 数据层/恢复 |
| F07 | 备份过程中并发删除附件 | 备份屏障保证一致；所有引用文件存在并通过哈希；不能成功产出缺文件残包 | backup/数据层 |
| F08 | 恢复解压磁盘满、损坏 ZIP、路径穿越/恶意压缩包 | 明确失败；旧档案目录与 current 指针不变；无越界落盘；成功切换前保持恢复原子性 | backup/restore + 隔离磁盘实测 |
| F09 | 恶意附件、附件名/正文提示注入、主动内容 | 不执行附件或正文指令；不获得工具权限；模型输出即使错误也不能绕过校验和用户确认 | 导入/AI + 界面 |
| F10 | AI 非法 JSON/枚举/日期/引用、误关联、慢响应、失败、取消 | 正式字段不变；可手动回退；不自动计费重试；报告错误建议/误关联数量及分母，不能只报 JSON 成功率 | 固定响应自动化 + 选定真实服务走查 |
| F11 | 合成 Key、Cookie、密码、URL token，以及无 ATS 规则裸 code/key；导入成功/失败/取消 | 禁采标记不进意图、档案、日志、备份；导入源路径不持久化；外发只含用户预览批准的内容；发布包无夹具/个人数据 | 隐私测试 + 请求/文件检查 |
| F12 | 未授权扩展来源、缺失/错误身份、不兼容协议 | 握手/信封按 D05 接受或拒绝；health/handshake 不带档案身份；错误可诊断且无业务写入 | 协议 + 真实 NM |
| F13 | 系统提醒授权后杀进程、跨次日、休眠唤醒、重启、主动退出 | 分别记录 OS 投递与应用内待办；不混淆关窗/退出；OS 限制写入支持范围；不偷偷开机启动、不重复投递 | 真实 OS；调度纯逻辑辅测 |

真实服务 AI 走查记录提供商、模型、日期、样本与结果，不把非确定性的模型判断当作数据安全防线。密钥通过既有凭据机制配置，不进入报告或网络抓包附件。

## 7. 验收环境与证据格式

必测 Windows x64 普通用户 + 真实 Chrome、真实 Edge。记录 Windows build、浏览器完整版本、WebView2 版本、安装方式、插件来源/ID、桌面/插件版本、protocolVersion、签名状态。最低支持系统版本须有相应安装证据；没有证据则不能直接宣称支持。

使用隔离测试账户或可回滚 VM、合成档案和测试浏览器 Profile。注册/卸载/磁盘故障的测试操作仅作用于该环境；清理脚本必须根据本次运行记录恢复，不按宽泛名称删除注册项或目录。

每次运行在 `docs/desktop-mvp/acceptance/runs/<run-id>/` 保存小型 Markdown/JSON 报告。大截图、录像和安装包放可访问的制品存储并链接，避免提交大二进制。

最少字段：

```text
runId, fixtureVersion, testedSourceCommit
desktopVersion, extensionVersion, protocolVersion
desktopArtifact { name, sha256, downloadUrl }
extensionArtifact { name, sha256, downloadUrl }
environment { osBuild, browser, browserVersion, webview2Version, accountType }
cases[] { id, status, testLayer, expected, actual, evidence, defect }
dependencies[] { issue, implementationPrs, acceptanceEvidence, signedOff }
review { reviewer, reviewedAt, decision, blockingDefects }
```

case 状态为 `PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE`；后者须引用已批准的范围决定。必测项 `BLOCKED` 或 `NOT_RUN` 均不能通过首发门禁。`PASS` 必须有运行结果，不能把空模板勾成通过。

## 8. 发布门禁与严重性

以下默认阻断：数据丢失/损坏、跨档案串写、永久删除后复活、未确认状态变化、附件越界或泄漏、密钥/禁采数据外泄、必测环境不能安装连接、插件独立填写失效、恢复破坏旧库、发行文件与验收对象不一致。阻断缺陷修复后重跑受影响旅程与回归。

非阻断项须记录影响范围、可行规避方法、负责人和后续 issue，并在支持说明中披露。OS 通知限制只有经过设计规定的降级流程、同步产品承诺并通过相应验收后，才能作为明确支持限制；不能仅贴「已知问题」跳过未兑现的承诺。

发布顺序：

1. D13 提供候选安装包和插件 ZIP，登记精确源码 SHA、版本、协议及 SHA-256；从候选下载渠道取回文件核验。
2. T4/T5 用这些文件验收。实际加载插件来自解压后的 ZIP；运行文件来自安装目录。若浏览器必须人工安装，按清单执行并记录。
3. T6 校验所有必测 case、依赖签收、证据引用、阻断缺陷、版本与产物哈希。自动校验只证明报告完整性；人工证据仍需具名审阅。
4. 确认最终发布 commit 的配置、文档、测试与产物一致，审查规则中的可操作意见均有处理结果；将已验收的同一组字节提升为正式 Release。
5. 发布后从正式下载地址再次取回安装包和 ZIP，复验哈希、版本、协议、安装路径、实际运行文件及最小连接/填写流程，归档最终记录。

候选源码或产物改变必须重新登记并按影响重验。证据报告可以在后续文档 commit 归档，但须明确区分报告 commit 和被测源码 commit；不得用「只改文档」掩盖发布包实际包含文件的变化。
